# 评测结果与指标口径

> 评测集：内部 100 题冻结集（40 事实 / 20 计算 / 20 边界 / 15 拒答 / 5 多轮），**不随仓库发布**。
> 五组配置：`configs/A_baseline.yaml` … `E_production.yaml`，同一评测集、同一模型、同一提示词，只切换检索/后处理模块。

## 1. 指标定义

| 指标 | 定义 | 实现方式 |
|---|---|---|
| 规则正确率 | 该题的全部规则判据通过 | 规则（关键字 / 数值 / 拒答 / 误拒） |
| judge 正确率 | 与标准答案语义一致且关键条件完整 | LLM judge（提示词版本化） |
| 数值精确率 | 计算题的期望数值正确；有工具时还要求工具返回值与人工手算一致 | 规则 |
| 路由准确率 | 期望工具被调用 | 规则（工具轨迹） |
| 拒答准确率 | 应拒答题真的拒答且没有编造 | 规则 |
| 误拒率 | 可答题被判为"答不上来"的比例 | 规则 |
| 引用支撑 | 每条引用的原句能在检索片段里逐字找到 | 规则（子串校验） |
| 忠实率 | judge 未发现上下文不支持的产品政策/数字主张 | LLM judge |
| 期望章节命中 | top-5 上下文中是否包含期望章节 | 规则 |

## 2. 消融结果

| 组 | 配置 | 规则正确率 | judge 正确率 | 数值精确率 | 拒答 | 误拒率 | 引用支撑 | 忠实率 | 期望章节命中 | p95 延迟 |
|---|---|---|---|---|---|---|---|---|---|---|
| A | 单路向量检索（固定长度切分） | 23.0% | 13.0% | 50.0% | 100% | 84.7% | — | 97% | — | 4.69s |
| B | + 结构感知切分 / 元数据 / small-to-big | 73.0% | 67.0% | 100% | 100% | 29.4% | — | 98% | 65.9% | 7.76s |
| C | + BM25 混合检索（加权融合） | 95.0% | 89.0% | 100% | 100% | 0% | — | 100% | 97.7% | 5.21s |
| D | + 重排（bge-reranker） | 96.0% | 92.0% | 100% | 93.3% | 0% | — | 99% | 100% | 5.00s |
| **E** | **+ 两级阈值拒答 + 引用校验 + 工具化计算（生产）** | **100%** | **100%** | **100%** | **100%** | **0%** | **100%** | 80% | 100% | 14.18s |

## 3. 结论

1. **结构感知切分是最大的单点收益**：A→B 规则正确率 23% → 73%，误拒率 84.7% → 29.4%。固定长度切分把"档位 + 额度"这类成组信息切散，模型只能回答"我不知道"；章节全文回填后条件与结论同现。
2. **混合检索补上精确匹配**：B→C 73% → 95%，误拒率归零。"专业版""50001 次"这类档位名 + 数字是 BM25 的强项，纯向量会混淆属性相近的档位。
3. **重排的价值主要在拒答**：C→D 答案正确率只 +1pp，但期望章节命中达到 100%，并且提供了做阈值拒答所需的绝对分数。
4. **工具化让"正确"可审计**：D→E 的数值 100% 是"工具返回值 = 人工手算"且关键数字出现在回答里；87 条引用全部逐字可验证；路由 21/21。
5. **代价是延迟与冗余**：E 组 p95 14.18s（设计目标 6s 未达成），忠实率 80%——回答更长，会外推相邻规则（例如把"AI 额度每月 1 日重置"外推到 API 额度）。

## 4. 拒答阈值标定

对 60 道可答（事实/边界）+ 15 道超范围问题扫描"最高重排分"阈值：

| 阈值 | 应答题通过率 | 误拒率 | 超范围拒答率 |
|---|---|---|---|
| 0.05 | 100% | 0% | 80.0% |
| 0.15 | 98.3% | 1.7% | 93.3% |
| 0.22 | 98.3% | 1.7% | 100% |
| 0.30 | 95.0% | 5.0% | 100% |

取相邻样本中点 **0.22**：误拒 1/60、超范围拒答 15/15。样本中正负分数有重叠
（1 条低分正样本 0.1451、1 条高分负样本 0.2115），这也是报告中保留"失败案例"的原因。

## 5. 复现

> 以下命令需要自备私有评测集（放在 `data/eval/`，该目录已被 `.gitignore` 忽略）。

```bash
# 1) 校验评测集（kb_anchor 逐字命中知识库、分布、字段完整性）
python scripts/make_eval_set.py --verify --out docs/eval_set.md

# 2) 跑一组（judge 可选，较费 token；--concurrency 控制并发）
python -m customer_service_assistant.eval.runner \
  --config configs/E_production.yaml --judge --concurrency 3

# 3) 渲染报告（读取 data/eval/results/*.summary.json）
python -m customer_service_assistant.eval.runner --render docs/ablation.md

# 4) 拒答阈值标定（需要可答 + 超范围样本）
python scripts/calibrate_threshold.py --probe-set data/eval/golden_set.jsonl \
  --refuse-set data/eval/golden_set.jsonl --out docs/threshold_calibration.md
```

## 6. 局限

- 评测集为自建（LLM 生成候选 + 人工审核 + 知识库原文锚点校验），不是对抗集；E 组的 100% 不代表开放场景。
- LLM judge 只用于软性指标，所有硬指标（数值、拒答、路由、引用逐字）都由规则给出。
- 每组只跑一遍，没有做重复运行的方差估计。
- 计算题与多轮题不参与检索阈值标定：它们的可答性取决于工具与对话历史，而非检索分数。
